# Working Rules

1. Read all of `context/` before changing any code.
2. Edit `context/` only when pushing to GitHub. Update it in the same push as the code change it describes.
3. Keep context consistent. If a conflict appears between files, code, or a teammate's note, stop and ask the developer. Do not guess.
4. Write minimal code. No unnecessary files, abstractions, or comments.
5. Follow sound design principles, but keep token usage economical.
6. Stay on the hackathon problem statement in `notes.md`.
7. Break problems and questions into separate labeled sections before working on them.
8. Commit and push only when the developer asks.
